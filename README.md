# 📎 对话窗口文件引用（qwenpaw-editor-ask）v0.1.0

在 **QwenPaw 官方对话窗口**里就地打开**工作区文件面板**看文件、选代码、一键引用到输入框提问的**纯前端插件**。
（旧名「对话窗口选区提问」—— 名字里没说清"看的是工作区文件"。）

![qwenpaw-editor-ask](https://raw.githubusercontent.com/chcsyf/qwenpaw-editor-ask/main/qwenpaw-editor-ask.png)


- 对话窗口右上角工具区多一个 **📎** 按钮（在「打开工作区」旁边）
- 点开 → 在对话栏**左侧**展开文件面板（**不遮挡输入框**）：
  - 左：工作区文件树（懒加载，根可在「项目目录 / 工作区」间切换）
  - 右：Monaco 只读预览（20+ 语言语法高亮，**只预览文本文件**）
- **选中代码 → 点「➤ 送到对话」（或 Monaco 内 `Ctrl+K`）** → 引用块自动写入当前对话输入框，光标停在末尾，接着输入问题回车发送即可
- 面板可**拖动标题栏**移动位置、**拖四周 / 四角**调整大小（几何记忆）；点标题栏的 **⌖** 恢复"自动贴靠输入框上方"
- 左栏与右侧预览之间可**拖拽分隔条**调整文件列表宽度（双击复位）；面板拉宽只加宽右侧预览，左栏宽度不变
- 文件树行**右键菜单**：插入路径到对话 / `@` 引用到对话 / 打开预览 / 复制路径

写入输入框的内容形如：

```
关于 QwenPaw/qwenpaw-code-editor/ui/index.js:140-168：

```javascript
// ……选中的代码……
```

```

## 面板操作

| 操作 | 效果 |
|---|---|
| 拖标题栏 | 移动面板（转为手动定位，位置记忆） |
| 拖四边 / 四角 | 调整面板大小（最小 320×180，不超出视口） |
| 拖**左栏与预览之间的分隔条** | 调整文件列表宽度（90px ~ 面板宽 −150px，记忆）；**双击复位** 180px |
| 拖**左边缘**（未手动定位时） | 只改宽度，仍自动跟随输入框位置 |
| `⌖` | 清掉手动几何，回到「自动贴靠输入框上方」 |
| 拖拽中按 `Esc` | 取消本次拖动 / 缩放，几何不落库 |
| 文件树行右键 | 插入路径到对话 / `@` 引用到对话 / 打开预览 / 复制路径（Esc、点别处、滚轮都能关） |

> **左右分栏的宽度关系**：左栏是**固定 px**（默认 180），所以**把面板拉宽时只有右侧预览变宽**、
> 左栏保持不变；面板被拖窄时按需自动压小左栏，保证预览区至少还有 150px。

右键的**插入路径**会插到输入框**光标处**（自动补空格），不是追加到末尾；`@` 引用那一项与宿主自带
「在聊天中引用」的格式完全一致（`@ <路径> `，较新构建会渲染成文件引用 chip）。

## 二进制文件不预览

只预览**文本文件**，两层判定：

1. **扩展名**：白名单（`.py/.js/.md/.json/...`，含 `.mjs/.cjs/.lua/.vue/.svg` 等 80+ 种）+ 黑名单
   （图片 / PDF / 压缩包 / 音视频 / 可执行 / 字体 / 数据集 / 模型权重…），并参考平台
   `/api/workspace/tree` 自带 `preview_kind`；
2. **内容嗅探**：真正读到内容后再查 NUL 字节与大量替换字符（`U+FFFD`）/ 控制字符。

图片、PDF、`preview.png` 这类文件**连 `/file-content` 都不请求**，右侧直接给出「不做文本预览」说明 +
路径 + 「插入路径到对话」按钮；文件树里它们的图标是 🗄、名字淡显。**路径照样可以用右键插入对话**，
只是不在编辑器里打开——插件不做图片 / PDF / 二进制渲染。

## 为什么是纯前端

- 会话、模型、工具全部复用当前对话窗口的上下文，**不新建会话、不新开标签页**
- 无后端进程；文件读取走平台自带接口（`GET /api/workspace/tree`、`GET /api/workspace/file-content`），
  认证头由宿主 `window.QwenPaw.host.fetch` 自动注入
- 面板位置按输入框实际位置计算（停在对话栏左侧），窗口缩放自动跟随
- 注入输入框这一段与宿主**同一套机制**：宿主内部「在聊天中引用」也是查 `[class*="sender"] textarea`、
  用原生 value setter 写值再派发 `input` 事件

## 安装

```bash
qwenpaw plugin install <本插件目录> --force
```

装完刷新平台页面即可（纯前端热加载）。打开对话窗口，右上角应出现 📎 按钮。

> 首次点开文件需从 CDN（jsdelivr）加载 Monaco Editor（约 5MB），约 3~8 秒；
> 若浏览器访问不了外网，面板会给出明确提示（不影响对话本身）。

## 实现说明（重要）

Console 的编辑器实例 / 草稿 / 引用 chip 全在 bundle 闭包内，插件**没有**公开 API 可以直接
调用；唯一可行的注入点是输入框 DOM：

1. 当前构建的对话输入框是普通 `<textarea>` → 用 `HTMLTextAreaElement.prototype.value` 原生
   setter + 派发 `input` 事件，让 React 受控组件接受外部文本（**已在真实 Console 实测有效**）；
2. 若某些构建启用富文本输入框（`contenteditable`）→ 回退 `document.execCommand("insertText")`；
3. 两者都失败 → 自动**复制到剪贴板**并提示手动粘贴（绝不静默失败）。

因此升级 QwenPaw 后若注入失效，退路是「复制引用」按钮，行为不会丢。

## 已知边界

- 只读预览（本插件目标是「选中 → 提问」，写文件请用「📝 代码编辑器」插件）
- **只预览文本文件**：图片 / PDF / 二进制一律不在插件里打开（给提示 + 可插入路径）
- 单次发送上限 300 行 / 30000 字符（超出自动截断并标注）
- 不做自动发送：文本进输入框后由你确认、回车发出
- 性能：拖动 / 缩放期间只写 DOM（rAF 节流），松手才提交状态——拖动过程中不改 React 状态

## 错误处理（三档降级 + 可重试）

| 场景 | 行为 |
|---|---|
| 注入成功 | 提示「已送到对话输入框（N 行）」/「已把路径插入输入框」 |
| 写入后被宿主回滚 / 输入框禁用 | 提示原因，并**自动复制到剪贴板**让你手动粘贴 |
| 当前页没有对话输入框 | 明确提示「请先打开一个会话」 |
| 点了二进制 / 不可预览的文件 | 右侧说明原因（含文件类型与路径）+「插入路径到对话」按钮，**不发起文件请求** |
| 扩展名像文本但内容不是 | 嗅探拦下（NUL 字节 / 大量乱码），同样走「不预览」提示 |
| 文件树 / 文件读取失败 | 树内显示原因 + **重试**按钮；网络错误提示「请求失败：…」 |
| Monaco CDN 失败或超时（20s） | 面板内显示原因 + **重试**按钮（重置加载状态） |
| 文件为空 / 目录条目超 500 | 明确提示，不静默 |
